# Tool reference

> Generated by `python scripts/gen_tools_doc.py`. Do not edit by hand.

Every tool also accepts an optional `user_id` (stdio mode only; ignored over authenticated HTTP).
A trailing `?` marks an optional parameter.

## Setup and preferences

| Tool | Parameters | What it does |
|---|---|---|
| `set_preferences` | `topics`: array, `level`?: string | SETUP: replace the user's topic list. Topics are chosen BY THE USER, can be anything and several at once (e.g. ["sysadmin", "devops", "network engineer"]). All get the same starting level (it adapts later). Afterwards propose 6-10 subtopics per topic and save them with set_topic, or offer a certification track (list_tracks). |
| `set_topic` | `name`: string, `level`?: string, `subtopics`?: array/null, `auto_adjust`?: boolean/null | Add or update ONE topic: its level, its subtopics (replaces the list), and whether the level adapts automatically (auto_adjust). Setting a level manually restarts adaptation from now. |
| `remove_topic` | `name`: string | Drop one topic (history is kept). |
| `set_question_types` | `enabled`: array | Choose which question types the user wants (empty list = all). |
| `list_question_types` | none | All question types: how to write them, how the user answers, how they are graded. |
| `set_settings` | `daily_goal_xp`?: integer, `timezone_name`?: string | Set the daily XP goal (default 20) and/or the user's IANA timezone (e.g. 'Europe/Kyiv'). The timezone decides when 'today' starts, which matters for streaks. |
| `get_preferences` | none | Topics (level, auto-adjust, subtopics), question types, goal, timezone, data location. If configured is false, run SETUP: ask which topics (any, several allowed) and level. |

## Certification tracks

| Tool | Parameters | What it does |
|---|---|---|
| `list_tracks` | none | Certification/learning tracks the user can start (exam objectives become subtopics). |
| `start_track` | `track_id`: string, `level`?: string | Add a certification track as a topic; its objectives become subtopics so get_coverage can show which objectives are still untouched. |
| `get_coverage` | `topic`: string | Objective coverage for one topic (great for certification tracks): which subtopics are untouched, which are weak, and the overall coverage %. |

## Your own material

| Tool | Parameters | What it does |
|---|---|---|
| `add_material` | `title`: string, `content`: string, `topics`?: array/null | Store the user's own material (notes, runbook, postmortem, docs) so some questions are grounded in it. Content is split into chunks of about 1500 characters. topics = which of the user's topics it belongs to (empty = any). |
| `list_materials` | none | The user's stored materials. |
| `remove_material` | `material_id`: integer | Delete a stored material. |

## Asking questions

| Tool | Parameters | What it does |
|---|---|---|
| `get_next_question_brief` | `topic`?: string, `from_material`?: boolean, `session_id`?: integer | ASK step 1. Returns exactly what to write: topic(s), subtopic, level, question TYPE, writing instructions, the REQUIRED answer position, and what to avoid. Overdue spaced-repetition reviews are served first (alternating with new questions). Optional: topic = user asked for one topic now; from_material = ground the question in the user's own material. Write ONE question, then store it with save_question. Never reveal the answer. |
| `save_question` | `topics`: array, `qtype`: string, `question`: string, `concept`: string, `correct_answer`?: string, `answer_key`?: object/null, `key_points`?: array/null, `explanation`?: string, `subtopic`?: string, `hint`?: string, `review_id`?: integer, `session_id`?: integer, `material_id`?: integer | ASK step 2: store the question you wrote. Use the topics/qtype from the brief and put the correct answer where the brief REQUIRED it (answer_key must match required_answer_key). concept = 2-6 word tag of the single idea tested. correct_answer = readable answer text. key_points = what a good free-text answer contains. The server rejects duplicates and wrong answer positions: fix and resend. Then show the user ONLY the question + reply format. |

## Sessions

| Tool | Parameters | What it does |
|---|---|---|
| `start_session` | `n`?: integer | Start a lesson of n questions (default 5, max 20) asked one at a time, ending with a summary. Then loop: get_next_question_brief(session_id) -> write -> save_question -> user answers -> check_answer/record_result -> next, until the session reports done. |
| `get_session` | `session_id`: integer | Progress of a session (and its summary once finished). |

## Evaluating answers

| Tool | Parameters | What it does |
|---|---|---|
| `get_pending_question` | none | The latest unanswered question with its answer key and grading guide (for you, not the user). |
| `check_answer` | `question_id`: integer, `user_answer`: string | EVALUATE step 1: ALWAYS call this first with the user's raw reply. For letters, ordering, matching, true/false verdicts and accepted commands it grades exactly and records XP/streak itself (auto_graded=true): then just explain. Otherwise (auto_graded=false) it tells you how to judge, and you finish with record_result. bad_format=true means ask the user to reformat; the question stays open. |
| `record_result` | `question_id`: integer, `result`: string, `user_answer`?: string | EVALUATE step 2 (only when check_answer said auto_graded=false): record 'correct', 'partial' or 'wrong'. Awards XP, updates streak, schedules spaced repetition, adapts the level. Then explain why the right answer is right, why the tempting wrong one fails, and add one real-world gotcha. |
| `use_hint` | `question_id`: integer | The user asked for a hint. Returns it; XP for this question is halved. |
| `skip_question` | `question_id`: integer | The user skipped the question: no XP, no streak. Counts toward a session's length. |

## Progress and review

| Tool | Parameters | What it does |
|---|---|---|
| `get_progress` | none | XP, streak (with freezes), daily goal, accuracy per topic and per question type, weakest topic/type, review queue. Use for 'how am I doing?' / 'where is my progress?'. |
| `weekly_recap` | none | Data for a weekly recap: this week vs last week (questions, accuracy, XP, active days), topic deltas, improved/weakest areas, streak, reviews mastered. Write the recap yourself. |
| `review_mistakes` | `limit`?: integer, `topic`?: string | Past wrong/partial answers with the right answer and explanation, newest first. |
| `get_due_reviews` | none | Spaced-repetition queue: what is due now and what is coming in the next 7 days. |
